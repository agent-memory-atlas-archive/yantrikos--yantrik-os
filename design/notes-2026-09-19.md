# Notes workbench — September 19, 2026

Native `apps/notes` is now a focused Markdown notebook, using the existing `~/.local/share/yantrik/notes` vault. The shell continues launching the native Notes window; no shell or compositor replacement is required.

## Workspace

- Notebook sidebar (type a notebook name into the note's Notebook field), All, Pinned, Recent (seven days), and Trash.
- Search across text and metadata, using Unicode lowercase matching. Search clearing restores the current folder.
- Comfortable wrapped writing, focus mode, word count, saved/error status, light/dark themes and shared accent preference.
- Markdown block preview: headings, paragraphs, lists, checkboxes, quotes and fenced code. Inline emphasis is shown as plain text; this is not a full HTML/browser renderer. Images and remote resources are not loaded.
- Import a local UTF-8 Markdown file as a new note; export to a new path without overwriting an existing file.
- Ctrl+N new; Ctrl+S save now; Ctrl+F library search; Ctrl+E focus; Ctrl+P preview; Ctrl+Z undo; Ctrl+Shift+Z / Ctrl+Y redo; F5 refresh.

## Persistence and limits

Notes remain ordinary `.md` files and `.meta` sidecars. Existing `pinned:` and `tags:` fields are retained; `notebook:` is an additive sidecar field. The native app accesses this vault directly, avoiding the previous service/fallback ID mismatch and synchronous service calls on the UI thread. Other writers should use Refresh to update the displayed library; baseline comparisons detect disk conflicts at save time. This is not a filesystem locking protocol with other applications.

One worker serializes filesystem operations. A single-shot 750 ms debounce schedules autosave; there is no repeating filesystem scan or application refresh timer. Typing remains enabled while a save runs, and subsequent edits are saved in the next generation. Switching/new/delete first saves the current draft. A failed save keeps the draft and cancels navigation. Closing waits for outstanding work or saves the current draft; failed saves leave the window open.

Saves write a private journal before updating the note. Same-directory temporary files, file fsync, atomic rename, and directory fsync protect individual file publication. Content and metadata are two files, so the write-ahead journal recovers an interrupted pair. A conflicting/interrupted draft is recovered as a separate note, preserving the disk version. A sudden crash can lose typing since the most recent 750 ms autosave checkpoint. Power loss can leave a redundant recovery/Trash record, which favors retaining content.

Trash is private to Notes (`.trash-v2`), retains content plus metadata, and has no automatic purge. Restore refuses a filename collision. Export and new-note publication do not overwrite existing files. Symlinks/special files are refused on read, read-only and multiply hardlinked targets are refused on replacement, and reads are bounded before allocation. Normal conflict checks do not promise protection from adversarial concurrent path replacement.

Bounds: 256 KiB and 10,000 newline separators per note; 2,000 notes for native creation/import; 32 MiB library text budget; 8 KiB sidecars. Vault scans inspect at most 10,001 directory entries and up to 2,000 Trash entries; unhandled files remain on disk. Undo/redo uses at most 64 text snapshots and 2 MiB per direction, and resets on note navigation. Slint's built-in undo had a cross-note byte-offset crash; keyboard undo is explicitly intercepted by the native controller. These model limits are not a strict process-memory bound.

When `LIBGL_ALWAYS_SOFTWARE=1` and the backend is the default `winit`, Notes selects `winit-software` to avoid software-emulated OpenGL. Explicit renderer settings are honored.

The old standalone prototype's assistant rail, image attachment browser, templates, and stub history/meeting controls are not in this focused native workbench. Existing attachments and note syntax remain untouched in the vault. This change does not upgrade the shell's legacy embedded Notes screen or the standalone notes service.

## Verification and deployment

Three test groups exercise the real storage and native Slint window: compatibility and atomic writes/conflicts/recovery; Trash/restore/collisions and bounded special-file reads; physical key events, autosave, switching, undo/redo isolation, search, notebook metadata, preview, theme rendering, failure recovery, and zero redraws for one second after focus loss and settling.

Native VM testing also exposed focus loss when switching to Preview and on an empty launch. The controller now explicitly focuses the shortcut scope when there is no visible editor, and restores content focus when hiding the sidebar or leaving a dialog. Tests cover these keyboard transitions.
