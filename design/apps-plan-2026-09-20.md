# The remaining apps, and an OS a mind can actually work in

Written 20 September 2026, after Calendar and Images both turned out to be facades and a survey
of the eleven apps not yet touched. Every claim about an app below was read out of its source;
the four that the plan leans on hardest were re-checked by hand.

## What the survey found

Calendar and Images were not unlucky. The same three faults run through the rest of the fleet.

**Fabricated success.** An action reports done without looking. Container Manager discards the
exit status of all nine `docker` mutations while its surface answers `{"removed": name}` — on an
action graded `dangerous`. System Monitor's `kill_process`, also `dangerous`, answers
`{"killed": pid}` whether the service call, the local fallback, or neither worked. Weather's
`add_location` answers `{"added": name}` when geocoding failed. Email's `mark_read`, `flag` and
"Synced" are unconditional. This is `add_event` again, in four more apps.

**The unset `in` property.** New, and the reason these apps photograph as working. Slint declares
a default, Rust never writes it, and the default is read as a measurement. Spreadsheet's
`cell-grid` is never populated, so `row_count() == 0` and the guards in cell-click, cell-edit and
the formula bar all fail: a perfect 50×26 grid that no mouse and no mind can type into. Network
Manager's `firewall-enabled` is a hardcoded `false` drawn in warning colour — the "Firewall Off"
the audit recorded as a finding is a default the app never looked up. Document Editor's
`doc-file-path` is never set, so Save always takes its early return and the `fs::write` beneath it
is dead code. None of this is visible to a grep of the Rust alone.

**Nothing is kept.** No app among the eleven has a store. Weather has a `save()` that is never
called, so saved cities and °C/°F vanish on restart while `new()` reads the file back and makes
the round trip look complete. Snippets' save handler is `let _ = (code, tags); // suppress unused
warnings` and the next selection overwrites the editor from the stale model, so edits revert
while you watch. Presentation's Save and Load are log lines. Downloads forgets its list and
orphans every partial file.

And one shape predicts all of it: **a large shared screen behind a small `main.rs`.** Network
Manager is 2506 lines of Slint driven by 235 of Rust; Music 2168 by 312; Spreadsheet 1249 by 156.
Download Manager is the only app where the logic outweighs the paint (1622 to 1234), and the only
one the audit called a gold standard.

## The contract

What "agentic" has to mean for one of our own apps, as things a script can check. Calendar and
Images now meet it; this is the bar for the rest.

1. **It opens.** A process and a compositor window, not `accepted: true`. A launch that dies is
   in `failed_launches`.
2. **It does its one job, and the store agrees.** Verified against what is on disk or in the
   service, never against the action's own answer.
3. **Actions report what happened.** The id it was stored under, the exit status, the thing that
   changed. A refusal names its reason. A turn on screen says `file_unchanged`.
4. **Failure is said twice.** On screen for the person, in `describe.notice` for the mind.
5. **It takes work from outside.** A path on the command line, an `open` action, a second launch
   handing over to the first. Today only Editor and Images do; no `.desktop` file has a `%f`.
6. **It survives a restart.** What was made is still there.
7. **No dead controls.** A button does something or is absent. `docs/app-control.md` already says
   an app whose data is a stub should not publish a surface; the same goes for a button.
8. **One owner per domain.** App, service and the mind's own tools reach the same store through
   the same typed contract.
9. **Grades mean it.** Anything that changes the machine or reaches outward is graded, and a
   `dangerous` action never answers success it did not observe.

## The machinery, before more apps

Fixing apps one at a time found two facades by hand. These make the next one impossible to ship.

**A conformance suite, which is the content of the release gate (#26).** `verify_calendar.py` and
`verify_images.py` were written ad hoc; they are the same script. One runner, one small probe file
per app declaring its one job and how to check it against the store. For each app: open it, assert
process and window, run the job, check the store, kill and reopen, check again, force the failure
and assert a refusal plus a notice. Exits nonzero. A mind may run it and diagnose; it may not
waive an assertion.

**A lint for the unset `in` property.** For every `in property` on an app's window, assert the
generated `set_…` is called somewhere in that app, or the property is on an explicit allowlist
with a reason. yantrik-mind already does this for config ("a dead form field is a lie" — its
schema test greps the source tree). This one check would have caught Spreadsheet, Network's
firewall reading, Document Editor's Save and Images' `file-name`.

**A lint for log-only handlers.** A callback whose whole body is `tracing::info!` or `|| {}`
fails the build unless allowlisted. The survey counted 41 of 44 in Spreadsheet, 40 of ~50 in
Document Editor, 20 in Music.

**Typed contracts for every service**, as Calendar now has: method constants and request structs
in `yantrik-ipc-contracts`, built by the app and parsed by the service, with payload tests. Email
already does this for `send_message`; Network's app calls five methods its service does not have.

**`service::ensure` wherever a service is on demand** — Email and Notes still have Calendar's
disease — and a **standard outcome**: a small shared helper so an action cannot return `Ok` without
passing through the result it observed, the way Download Manager's `settle()` already works.

## The apps, in three waves

### Wave 1 — tell the truth (small; the apps a mind will use for real work)

| App | The fault | The fix |
|---|---|---|
| Container Manager | Nine mutations discard the exit status; `remove` (`dangerous`) answers success regardless. "Docker missing" and "no containers" are both `vec![]`. | Propagate the result, as `on_ct_logs` eleven lines away already does. Report the runtime as absent, not empty. Rename the surface from `containers` to match the app. |
| System Monitor | `kill_process` (`dangerous`) fabricates success. Service failure silently degrades to local `sysinfo`, which is where the audit's empty `cpu_model` and `ip` came from. | A real result from the kill path; `degraded: true` and the source of each reading in `describe`. |
| Weather | `save()` is never called; `add_location` succeeds on a failed geocode. | Call it. An else branch. Grade the config actions once they store something. |
| Download Manager | No persistence: the list and every partial transfer are lost on restart. | A state file; resume `.part` files on start. It is otherwise the reference implementation. |

### Wave 2 — make the one job real (medium)

| App | The fault | The fix |
|---|---|---|
| Snippets | Save discards its payload and edits revert in-session. Copy — the app's purpose — is a log line. No store. | Save into the model, a JSON store, a real clipboard call, a surface (`new`, `save`, `copy`, `search`). |
| Presentation | Next/Prev move the index without `commit_current()` or `show()`, so the following commit writes slide N over slide N+1. Save and Load are log lines. | Two callbacks, a serializer, argv, a surface. The slide model is the best-built thing in the office trio. |
| Document Editor | Save is structurally unreachable. 40 dead handlers. Its AI rewrite path is real — it can rewrite a document nobody can save. | A path (argv, an `open` action, a save-as), then cut the formatting, history and track-changes controls that do nothing until something backs them. |

### Wave 3 — build it or take it off the shelf (large; needs a decision)

These three have nothing under the screen. The honest options are to build the minimum real
thing, or to remove the app from the launcher until someone does — shipping the drawing is the
option this plan rules out.

- **Music** — no playback engine, no scanner, no library. Minimum real: `mpv` over its IPC socket,
  a folder scan into a small library store, play/pause/next/queue, `open <file>`. Everything else
  on its 2168-line screen (playlists, folder watch, speed) goes until it is backed.
- **Network Manager** — the app calls `wifi_toggle/scan/connect/disconnect/forget`; the service
  has none of them, and the firewall reading is a default. Minimum real: those five over `nmcli`
  in the service, graded `sensitive`, plus a firewall state that is actually read. Bluetooth, VPN
  and diagnostics — eighteen dead handlers — come off the screen.
- **Spreadsheet** — no cell model and no formula engine; `is_formula` is `starts_with('=')`.
  Minimum real: a cell model, CSV load and save, arithmetic with references and
  SUM/AVG/MIN/MAX/COUNT. This is the largest piece of work in the plan.

**Email** was set aside, but two of its faults are cheap and worth knowing: its service is never
started, so a dead service is indistinguishable from "No account yet" — the audit's onboarding
screen may never have been about an account at all — and `on_save_account` takes all eight fields
of that form and logs them, so nobody can submit it.

## Beyond the apps

**One owner per domain.** The two-calendars split is general. The companion has its own `docker`,
`weather`, `media`, `wifi` and `network` tools that shell out beside the Containers, Weather,
Music and Network apps, and its calendar writes to a SQLite table the Calendar app never reads.
Two paths into one domain is how they drift. The rule: a domain has one service or store, and the
mind's tool for it is a thin caller of that contract. Calendar first, since the split is already
proven there.

**The mind should hear about failure without asking each app.** Every app's `notice` is already in
its own `describe`. The shell's `describe` should carry the recent ones, so "what went wrong on
this machine in the last ten minutes" is one read.

**Handing a file to an app should work everywhere.** `%f` in the `.desktop` files, MIME routes in
Files for documents, decks, sheets and audio, and the `open` action on each surface — so "open this
in…" is the same sentence for a person, for Files and for a mind.

**Watching work.** `describe` is a poll. A revision-keyed wait on the surface lets a mind watch a
download or a long copy without spinning, and it is the app-side half of durable runs (#25).

**Approvals on the actions that deserve them (#27).** `remove`, `kill_process` and every network
change are the first real customers for run-bound grants — and Wave 1 has to land first, because
a grant on an action that fabricates its outcome approves nothing.

**The asking surface itself.** From the film session, still open: Ctrl K is advertised twice and
has no key handler, and the Lens has no programmatic open; the companion's fallback drops the
user's question after a 429 in a tool round (`slim_messages`), which is what turns it red; the
startup brief fires on every shell start; background instincts post their non-decisions into the
chat panel. And roles on our Slint elements (#42), so the accessibility tree says what a thing is
as well as what it is called.

## Order

1. The conformance runner and the two lints, with Calendar and Images as its first passing
   entries. Two to three days, and it is the release gate's test content.
2. Wave 1, each app entering the suite as it is fixed. About a day each.
3. One owner for calendar, and failure aggregation in the shell.
4. Wave 2.
5. The Wave 3 decisions, then whichever of the three is kept.

Left alone on purpose: visual redesign of any app before it meets the contract. A better-looking
facade is a worse bug.
