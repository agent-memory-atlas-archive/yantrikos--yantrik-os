# Settings refinement — September 19, 2026

Settings remains part of the native Slint shell. This pass adds no runtime dependencies, background workers, polling loops, web views, or animations that run continuously.

## Experience

- Appearance keeps the desktop previews and real wallpaper thumbnails, with five directly selectable accent swatches. Pointer, keyboard, and accessibility activation use the same callback.
- A wider sidebar accommodates category labels. Search indexes controls such as wallpaper, Wi-Fi, model, and idle lock; Enter opens the first matching category, Escape clears the filter, and Ctrl+F focuses search.
- Desktop, Network, Accounts, Privacy, and System use consistent rows with descriptions and explicit values or actions. Network opens the installed native network manager.
- Save status stays visible in the footer; failures appear in a wrapped banner. Preference failures can be retried. Failed provider changes leave the form open and preserve the previous provider configuration.
- The existing AI provider, routing, budget, Skills, and Harnesses pages remain available.

## Accurate scope

The four account adapters are unavailable in this build; connection and sync callbacks no longer fabricate success or item counts. Incognito affects new built-in companion memories for the current session. The idle setting opens the shell lock view; it is explicitly not a compositor lock for other native windows. Native apps pick up saved appearance when reopened.

## Preference storage

Settings and provider YAML use bounded UTF-8 reads (256 KiB maximum), private temporary files, file synchronization, and atomic publication in the same directory. Existing top-level unknown keys are retained. Invalid YAML or typed values, external changes, symlinks, hard links, special files, and read-only files are preserved instead of overwritten. Temporary-file cleanup removes only a file successfully created by this save. A directory-sync error is reported after publication.

External-edit detection compares file contents twice, including immediately before publication. It is not a cross-process locking protocol against an uncooperative writer. Restarting the shell reloads externally edited preferences. Appearance previews may remain active in the current session after a save failure; the banner explicitly says they were not saved.

Do Not Disturb changes from Settings, the command palette, and the shell control API all use the persistent callback. Provider mutations roll back in-memory state if saving fails, before updating the displayed provider list or reloading the backend.

## Resource observation

Ten-second samples of the entire shell with Settings open measured 454,629 KiB PSS / 7.5% of one CPU core before, and 392,988 KiB PSS / 6.4% of one core after the final restart. These are whole-shell observations, including companion and system monitoring, with different process/cache lifetimes; they do not establish a Settings-only performance improvement. The shell remains about 384 MiB PSS and needs a dedicated memory/idle-CPU reduction pass to meet the broader lightweight goal. This change adds no recurring work or dependencies.
