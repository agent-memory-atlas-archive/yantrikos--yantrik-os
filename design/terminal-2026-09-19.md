# Native Terminal workbench

The standalone Terminal now opens a persistent interactive shell on a real Linux
PTY. Commands, environment variables, working directories, job control, and
interactive input survive between submissions. The first shell honors the launch
directory; subsequent tabs inherit the active shell's directory. The former implementation ran
each command synchronously on the UI thread and did not maintain a shell.

## Interface

The shared app header contains New tab and Find, with clipboard, text size,
Assistant, and Restart exited shell in More. Up to eight independent tabs show
their shell's directory and live/exited state. The ANSI canvas stays dark in both
OS themes; chrome follows the theme. Text uses the existing embedded monospace
font and ANSI 16/256/truecolor output. The cursor is steady.

Find searches the session's bounded history, updates with new output, and highlights matching lines.
Copy screen copies visible text; Paste uses bracketed paste when the shell
enables it. Closing a tab with a child process requires confirmation. The
assistant is collapsed initially and explains visible output only when requested.

| Shortcut | Action |
| --- | --- |
| Ctrl Shift T / W | New tab / close tab |
| Ctrl Page Down / Page Up | Next / previous tab |
| Ctrl Shift F | Find in history |
| Ctrl Shift C / V | Copy screen / paste |
| Ctrl + / - / 0 | Larger / smaller / reset text |
| Shift Page Up / Page Down | Scroll history |
| Ctrl C | Interrupt the foreground command |
| Escape | Close Find or cancel close confirmation |

## Resource and lifecycle decisions

- Existing Rust/Slint runtime and cached PTY/parser dependencies; no browser,
  new service, or downloaded font.
- One sleeping worker per shell waits on the PTY and a wake socket with `poll`.
  No periodic output polling or cursor timer.
- Coalesced output updates, at most one scheduled frame per 16 ms burst. An
  inactive session does not replace the active canvas model.
- 1,000 history lines; maximum 160 rows by 400 columns; eight tabs; bounded
  input queue and 64 KiB individual paste limit.
- Resize reaches both the terminal parser and the kernel PTY. Closing a session
  hangs up its shell/foreground job and reaps the shell, escalating if necessary.
  Whole-app shutdown joins the workers after the UI event loop ends.

## Automation compatibility

The Terminal control endpoint's `run` action now submits a command to the active
interactive PTY **asynchronously**. It returns `accepted`, `completed: false`, and
`shell_pid`. It no longer returns a fabricated synchronous per-command exit code.
Call `describe` for subsequent visible output and shell state. `shell_exit_code`
describes the shell process, not the last submitted command. `send_input` handles
interactive text/control characters; `new_tab` opens another shell.

## Validation and scope

Run in the Linux build environment:

```sh
CARGO_TARGET_DIR=/home/yantrik/target-yantrik cargo test --offline --profile fast -p yantrik-terminal
```

The core tests exercise persistent environment/cwd, interactive input, ANSI
colors, kernel resize, interrupt/exit, independent sessions, bounded history,
and child reaping. Window tests instantiate the production Slint component and
callbacks with real PTYs, a software window adapter, and a test clipboard. They
exercise keyboard input, tabs, clipboard, Find, close confirmation, restart,
compact layout, themes, and idle redraw requests. PNGs are written to `target/`.

All six tests passed on September 19. The actual native window with two real
shells requested zero redraws during a one-second idle observation after settling.
This measures redraw requests, not VM CPU or memory consumption. Reviewed renders:

## VM deployment

Deployed to VM 520 on September 19 at `192.168.4.44`, verified against its MAC
address on Proxmox node `192.168.4.151`. Only Terminal was replaced; the desktop
process remained PID 72714 throughout. The installed and running executable
hashes both match the final package. Rollback binary and verification report:

`/opt/yantrik/ui-deployments/terminal-20260919T203124Z/backup/bin/yantrik-terminal`

`/opt/yantrik/ui-deployments/terminal-20260919T203124Z/verification.json`

The live Wayland check caught a physical-key bug absent from the initial
synthetic tests: Slint's modifier key codes overlap control bytes, so Shift could
send Ctrl+P to the shell. Modifier key events are now filtered before shortcut
and PTY encoding; actual Ctrl+P/Ctrl+Q chords remain supported. The regression
test and native clipboard test pass with the corrected build.

Verified using native keyboard/window/clipboard tools: persistent environment
and cwd, independent tabs, keyboard tab switching and closure, copy/paste,
Find and Escape, Ctrl+C interrupt, and restore/maximize. Complete `stty size`
responses changed from 25×115 to 26×148. Reviewed the guest compositor's
[actual screenshot](previews/terminal-vm-2026-09-19.png), including a separate
Find capture. Terminal is left open with one idle shell in the home directory.

A 10-second idle sample of Terminal PID 87970 measured 0.0% of one CPU core,
99,407 KiB PSS and 149,920 KiB RSS. This is a short VM diagnostic sample, not a
general benchmark or a matched before/after comparison.

This is a standalone-app change; the shell's older embedded Terminal view is
separate. Split panes, text selection, terminal mouse reporting, image protocols,
and complete xterm query compatibility are not implemented. Existing terminal
lines do not reflow on resize. The native VM smoke test covers the workflows
above; it does not establish compatibility with every full-screen terminal app.
