## The loop that works

1. The mind on the machine audits the *running* system and writes a report with evidence.
2. Issues are filed from that report, each carrying the command and the output.
3. The worker in WSL fixes one issue at a time against the source, with tests.
4. A human — or a session with more care than usage — reviews the diff, then pushes.

Three things this loop caught that reading the source would not have:

- The accessibility switch (`org.a11y.Status.IsEnabled`) was false, so nothing published a widget
  tree. One property, and the whole "see without screenshots" capability was dark.
- The action grades were enforced only by the MCP bridge. `yos act` ran `dangerous` actions.
- An idle Terminal burns 1.5 cores.

## Two traps, both of which nearly produced a wrong report

**Installed is not running.** `yantrik-update apply` writes binaries and does not restart the
session. The first re-probe of the security fix still deleted the file, because the running shell
was eleven hours old. Always reboot, or check `ps -o etimes` on `yantrik-ui` against the binary's
mtime, before believing a verification.

**A refusal is not always the boundary you think.** Two probes of the grade hole "passed" because
`files_delete` resolves names against the files screen's *current* directory, so they failed at
not-found before any grade check ran. Use `files_go` to point the screen first, or the test proves
nothing.

## Running the queue

`~/queue.sh` in WSL works issues in order, one commit each, logging to `~/queue.log`. It never
pushes. To see where it is:

```sh
tail -20 ~/queue.log
cd ~/src/yos-work && git log --oneline fix/from-inside | head
```

To land what it has done, review the diff and then:

```sh
cd ~/src/yos-work && git format-patch -1 --stdout > /tmp/f.patch
cd /mnt/c/Users/sync/codes/yantrik-os && git am --keep-cr < /tmp/f.patch
```

Correct the commit trailer if it credits the wrong model: the worker writes
`Co-Authored-By: Claude Code`, and what actually wrote the change is `qwen3.8-max`.
