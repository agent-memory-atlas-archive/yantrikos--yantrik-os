# Files workbench — September 19, 2026

Files remains a native Slint view embedded in the shell. This change adds no browser runtime or always-running Files timer.

## Behavior

- Shared app header, places, breadcrumbs and editable location, folder search, list/grid views, on-demand details and text previews.
- Virtualized rows; a fixed selection toolbar avoids moving double-click targets. Arrow/Home/End navigation keeps selection visible. Ctrl/Shift multi-selection, clipboard shortcuts, Ctrl+L, Ctrl+F, F2, Delete, Space preview, and up to eight folder tabs.
- Directory listing and filesystem mutations run on workers. One mutation at a time; progress messages are throttled. Errors appear in the interface and in the shell control state.
- Copy publishes a completed temporary file/folder with an atomic no-replacement rename. Canceled copies remove their partial destination; cleanup failures report the temporary path. Already completed items stay completed. File and folder collisions never overwrite or merge.
- Moves use an atomic no-replacement rename. Symbolic links are transferred as links; recursive copy does not intentionally traverse them. Devices, sockets and pipes are refused.
- Delete moves to Yantrik's private recoverable Trash. Restore returns an item to its original path, refuses collisions, and keeps failed restores recoverable. Undo is available for the latest group of trashed entries. Empty Trash has a confirmation dialog.
- Open with routes to the default application or the embedded Text Editor. Open Terminal here creates an independent tab using a directory argument, without typing a shell command or changing an existing tab's working directory.
- The control surface reports directory loading, operation state/progress, notice, selection, clipboard, Trash and preview state. Asynchronous actions are marked deferred; callers must read state to confirm completion.

## Resource bounds and limitations

Directory listings stop at 50,000 entries. Text previews read at most 64 KiB and display at most 20 lines, each capped at 240 characters. Copy uses a 64 KiB buffer and a 128-level nesting limit. Selection size counts file bytes without walking directories. Grid mode creates visible rows rather than every cell in a large directory.

Cross-filesystem moves and moves to Trash are refused; copy then handle the original separately. Copy preserves basic permissions, but does not promise preservation of ACLs, extended attributes, hard-link relationships, timestamps, or sparse allocation. It is not a snapshot of files being concurrently edited. Directory paths/names must be UTF-8 for this UI. Refresh is manual (F5); there is no filesystem watcher. Previews are bounded text/details, not image thumbnails or a media renderer. Trash uses `XDG_DATA_HOME/yantrik/trash-v2`, not the freedesktop desktop-wide Trash, and does not migrate older private Trash stores.

## Validation

Seven isolated tests use the production file-operation and listing sources: collision/self-copy prevention, copy cancellation cleanup, symlink loop/broken-link handling, Trash restore/collision protection, invalid/create-existing names, bounded Unicode previews/exact size sorting, and nonblocking pipe preview.

The production Slint Files component requested zero redraws during a one-second idle observation with 1,000 entries. It passes an interaction probe with 1,000 entries: list/grid Home/End scrolling and hit targets, Shift selection, copy/cut/paste shortcuts, search and Escape, editable location, and new-folder submission. All six native Terminal tests pass, including creating a new tab in a path containing spaces and a literal semicolon while preserving the original session.

VM functional checks passed for multi-file copy, Unicode names, destination collisions, moves with broken links, rename collisions, Trash/restore/undo, creation, and opening Terminal in a new tab. Canceling a 2 GiB sparse test copy preserved the source and removed the partial destination. The VM's separate tmpfs `/tmp` also confirmed that unsupported cross-filesystem Trash moves preserve the source and show an error.

Native keyboard testing found two regressions absent from the original render checks: folder loading lost keyboard focus, and the shared input's one-way internal binding left old text visible after clearing its value. Both have targeted interaction regressions. The file assistant remains on demand in the details panel, with a bounded response and a polling timer only while a request is active. AI provider output is not covered by the filesystem smoke tests.
