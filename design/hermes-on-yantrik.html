After the review

What changed from the first draft

GPT-6 Astra argued the draft exposed the engine instead of designing the experience. Most of that held up. Where it did not — shell-side guessing, a boundary that looked like a permission — the second round fixed it.

Chat · Agent · Schedule mode switch
Ask · Start task… · Automate…

A person starts a task, not an agent — Hermes already is the agent. Enter asks; nothing turns into work without Ctrl+Enter or a click.

Guessing whether text is a task
Only certain results are automatic

The shell opens apps, files and settings it is sure of. Everything else is a question, so a wrong guess never starts real work.

The same run list in four places
One Activity, one chip, a four-row preview

Tasks no longer appear in the taskbar. The status bar says Hermes · Needs you 1, and Activity holds everything else.

Tool toggles next to "no booking"
Enforced controls, separate from instructions

The task draft shows what Hermes actually enforces apart from what it is only asked to do.

Approve inline, four equal buttons
A review sheet: Deny or Allow once

Nothing preselected, scope marked checked or not verified, and "Always allow" left out until Hermes can describe what it would grant.

A raw config.yaml tab in Settings
A form, plus "Open Hermes config folder"

The form covers the common settings, and the full file stays Hermes' own to edit. The shell never reads or passes it along.

Ctrl K, anywhere

The same composer, over whatever you are doing

Most of the day a window covers the desktop. Ctrl K brings the composer up over it without a blur, with the same buttons and keys. The submit hint always says what Enter will do — here it opens a file, because that result is exact.

How it connects

Hermes dials in. The OS never calls out.

Hermes has an HTTP API for all of this, but using it would mean the OS holding Hermes' address and key — which the harness rule forbids, and a test enforces. So Hermes attaches the way Yantrik Mind does, through a small platform plugin, and the harness protocol grows to carry tasks, events, approvals, automations and settings.

The rule still holds. Nothing in this list carries an address or a key to the OS. A key goes one way — from the form into Hermes — and comes back only as "set". None of these messages are Hermes-specific; Yantrik Mind can speak them too.

Build order

Each step ends on the machine, checked through yos

Nothing on screen can be real until Hermes is attached and sending events, so the protocol and the plugin come first.

  1. Protocol and host

    Tasks, events with sequence numbers and replay, approvals, automations and config in yantrik-harness, with the no-endpoint test kept.

    You'll seeyos describe shell reports tasks and automations.

  2. Hermes on the machine

    Hermes 0.14 as a user service using the LAN Ollama and YantrikDB memory, plus the Yantrik platform plugin.

    You'll seeHermes answering in the Companion panel.

  3. Composer

    Ask, Start task… and Automate… on the desktop and over apps with Ctrl K, including the task draft.

    You'll seeA task started from the desktop, with its enforced controls shown.

  4. Activity

    The status chip, the four-row preview, the task list and task detail, and "Connection lost" handled honestly.

    You'll seeA task started from Telegram showing up live on the desktop.

  5. Approvals

    The review sheet, scope checking for simple delete, move and permission commands, and one notification that doesn't steal focus.

    You'll seeRisky commands wait for you instead of failing.

  6. Automations

    The library and the editor, with timezone and next runs from Hermes' scheduler.

    You'll seeA weekday email summary that survives restarts.

  7. Mind settings

    The configuration form, the config folder, and switching minds with the handover and the memory check.

    You'll seeSwitch between Hermes and Yantrik Mind from Settings.

Drop the right rail?

At rest it is an empty column, and while work runs it repeats Activity. CPU, memory and services would move to a System panel in the status bar.

SuggestDrop it, and let the work column breathe.

Places instead of Project?

"No active project" has never been filled in. Places, favourites and recent files are always true.

SuggestReplace it, and bring projects back once you choose one on purpose.

One memory for both minds?

Their YantrikDB versions differ today, so sharing one file could break the older mind.

SuggestOne local YantrikDB service that both minds use, turned on only once both are confirmed compatible.
