# APPS.md — granular audit of every app Yantrik OS ships

Audited 2026-09-17/18, from inside the machine. Scope: the 16 apps in
`/opt/yantrik/share/applications` (each with a binary in `/opt/yantrik/bin`).

**Method.** Launch + time-to-window via `open_app` and polling the a11y service's window
list (`inside-report/probe.py`); control surfaces via `yos describe`; widget trees via the
OS's own `a11y` service (`a11y.windows` / `a11y.describe` / `a11y.act` over its unix
socket — raw `busctl` AT-SPI access was denied to this session, the a11y socket is the
sanctioned path); hands-on tests via each app's surface actions. Test content is named
"audit". No deletions, no email sent, no settings changed.

**Cross-cutting a11y findings** (true for all 14 apps that opened):

- Every window publishes a tree. Every element has a **name**. Every element's **role is
  empty**, and the describe summary is garbled as a result: `"Notes — 37 s"`, `"Weather —
  66 s"` (Chromium, by contrast, gets `"1 entry, 1 frame, 1 toggle button, 2 tool bars…"`).
  The yantrik apps publish names only; the bridge has nothing else to report.
- Trees are **flat** — no hierarchy, no parent/child, no states.
- Element **ids are unstable**: they are re-issued on every `a11y.describe` call, so a
  caller must describe and act in one breath.
- **`a11y.act` cannot drive anything.** On every yantrik app it fails with
  `Unknown interface 'org.a11y.atspi.Action'` (tried `click`, `activate`, `press`,
  `focus` on notes and music-player). On Chromium it fails differently and worse:
  `` `w4921` cannot `click`; it offers: , `` — the Action interface exists there but the
  service reads back **two blank action names**, so nothing can be named to invoke.
  The widget tree is read-only. Interactive parts are visible to the machine but not
  reachable by it.

Consequence: for the 8 apps with no control surface, there is **no programmatic path at
all**. A human with a mouse can use them; the OS's own minds cannot.

## 1. calendar

- **Opens:** was already running (pid 20637); `open_app` accepted, window "Calendar" present.
- **Surface:** `app-calendar`, 5 actions: `select_day(day)`, `show_month(direction)`,
  `go_to_today()`, `add_event(date, notes, time, title)`, `set_view(view)` — all standard,
  all "settles on return".
- **a11y:** 55 elements — month grid ("September 2026", Sun–Sat, day numbers), view
  switchers, "New Event", "AI". Names present, roles all empty.
- **For:** keeping a calendar. **Tried the one thing** — add an event:
  `add_event date=2026-09-17 time=23:45 title=audit` → `accepted: True, settled: True`,
  result `{"added":"audit","on":"2026-09-17 23:45"}`. **The event does not exist:**
  summary still "nothing on day 17", revision unchanged (`99a1a169…`),
  `days_with_events: []`, `events_this_month: 0`. Retried for 2026-09-18 (`audit2`):
  same fake success. `select_day day=18` → `events: []` (and *did* move the revision,
  proving state changes are visible — add_event simply doesn't write).
- **Broken/embarrassing:** the one job the app exists to do returns a **fabricated
  success**. Navigation works; storage doesn't. This is worse than an error.
- **Verdict: partial.**

## 2. container-manager

- **Opens:** 1.2 s → window "Containers" (pid 49594).
- **Surface:** `app-containers`, 6 actions: `refresh()`, `start(container)` [standard],
  `stop(container)`, `restart(container)` [sensitive], `show_logs(container)` [standard],
  `remove(container)` [**dangerous**].
- **a11y:** 19 elements — tabs Containers/Images/Volumes, "0 running / 0 stopped /
  0 total", "Image to run…" input, "Run New", docker context indicator.
- **For:** managing docker containers. **Tried:** `refresh` → `{"running":0,"total":0}`
  (docker is live, genuinely empty); error path `show_logs container=audit` → clean
  refusal `no container here is called "audit"`. Could not start/stop anything — nothing
  exists to manage, which is the correct state, not a failure.
- **Broken/embarrassing:** naming: the app is `container-manager`, the socket is
  `app-containers`; `yos describe container-manager` → "no socket". yos's own docstring
  brags about not making callers guess names — then does exactly that here.
- **Verdict: works.**

## 4. download-manager

- **Opens:** already running (pid 20659); window "Downloads".
- **Surface:** `app-download-manager`, 10 actions: `add(save_dir, sha256, url)`,
  `pause(id)`, `resume(id)`, `retry(id)`, `verify(id, sha256)`, `pause_all()`,
  `resume_all()`, `clear_completed()`, `open_folder(id)` [standard], `cancel(id)`
  [sensitive] — all "settles later" except `clear_completed`.
- **a11y:** 16 elements — counters ("0 active - 0 B/s - 0 done today"), Pause All /
  Resume All / Clear Completed, "Add URL", search, All/Active/Completed/Failed tabs.
- **For:** downloading files. **Tried the one thing:**
  - `add url=file:///etc/hostname` → refused with a *good* error: "is not an http(s) URL".
  - `add url=https://example.com/ save_dir=/tmp` → `accepted:true, settled:false` (honest!),
    queued → **completed in <4 s**: 559 B / 559 B, 100%, sha256 computed and shown.
  - `verify id=1 sha256=<the real hash>` → accepted, "verifying" (settles later, by design).
- **Broken/embarrassing:** minor — a URL with no filename saved as `download` rather
  than anything derived from the URL/path.
- **Verdict: works.** The most complete app in the fleet: real side effect, honest
  settle semantics, checksums, good refusals.

## Overall

- **works (6):** container-manager, download-manager, notes, system-monitor, terminal, weather
- **partial (8):** calendar, document-editor, email, music-player, network-manager,
  presentation, snippet-manager, spreadsheet
- **broken (2):** image-viewer, text-editor

The fleet splits in three: a **core six** with real control surfaces that survive
hands-on use (download-manager is the gold standard — honest `settled:false`, checksums,
clean refusals); an **office/empty eight** that render complete, attractive UIs no
programmatic caller can touch, because they ship no socket and the a11y Action interface
is missing everywhere (and blank-named even in Chromium, where it exists); and **two
corpses** that the OS accepts, logs as "Launching", and then never mentions again —
`failed_launches` stays empty while nothing runs.

The single worst bug is **calendar's `add_event` fabricating success** — an app that
lies is worse than an app that fails. The single worst systemic gap is the **read-only
a11y tree**: names without roles, unstable ids, no actions — the accessibility switch
lets the machine *see* every app but touch only the six that bothered to publish sockets.
